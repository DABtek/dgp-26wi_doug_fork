## Part 1: Gunner vs. Pilot

![[wwii-gunner-ball-turret.png]]

In a bomber plane, the operations of the aircraft are divided up into two people:
* Pilots, who get the aircraft to the proper geographical location and back
* Gunners, who take the proper action at that location, or along the way

Similarly, in many Battlecode strategies, there's a part of your code that is "pilot code", that moves or navigates your robots to the correct destination, and "gunner code" that takes the appropriate action. The "pilot code" usually needs to communicate with the "gunner code" via variables, and vice versa.

Changing between pilot and gunner code usually involves an `if` or `switch` statement in your code, and the value of one or more variables that determines which mode you are in.

For the first two questions, you can click on lines in GitHub to create a link with a *start* and *end* line, like this.

https://github.com/TheEvergreenStateCollege/dgp-26wi/blob/main/java/src/pathfinder/BugNav.java#L117-L126

b) Find two examples in your code of "gunner code". Submit a link to the range of lines that contain it. Describe how to choose a destination for the "gunner code" and why it's useful for your strategy.

c) What variables are used to communicate between the pilot and gunner code?

## Part 3: Unit Test

Add, commit, and push a unit test into your `java/test/<playerdirectory>` following [the example for `pathfinders`](https://github.com/TheEvergreenStateCollege/dgp-26wi/blob/main/java/test/pathfinder/RatKingTest.java) that tests some portion of your code. It should be three or more lines of code in the *body* of your test function. For example:

```java
@Test
	public void testOpposite() {
		RatKing rk = new RatKing(rc); // Line 1
		assertEquals(rk.centerXSignum, 1); // Line 2
		assertEquals(rk.centerYSignum, 1); // Line 3
	}
```

It can be a purely mathematical function, or it can use a MockRobotController to simulate or test some behavior in the game engine on a specially contrived map.

You can run your tests in the terminal, from the `java` directory, with this Gradle command

```
./gradlew test
```
